# 调研渠道与来源规则

## 渠道清单

**官方（结论级）**
- 公司官网「加入我们 / 校园招聘」页；
- 公司招聘系统页面（Moka、北森、飞书招聘、智联企业版）；
- 公司官方公众号的招聘推文（注意推文日期）；
- 招聘平台上的官方认证账号（BOSS 直聘、拉勾、实习僧、牛客校招页）。

**半官方（线索级）**
- 公司技术博客、GitHub 组织、论文作者单位、发布会与展会（世界机器人大会 WRC、CES、ICRA/IROS 展区）；
- 融资新闻（36氪、投中、机器人大讲堂等），只用来判断阶段与时间，不用来断定 HC。

**社区（网传级，必须标注）**
- 牛客网面经与 offer 帖、一亩三分地、脉脉、小红书、知乎、Blind 类社区；
- 只能作为「薪资区间」「面试流程」「团队氛围」的参考，写进 `jobs.json` 时
  `薪资来源` 记 `网传`、`薪资可信度` 记 `低` 或 `中`，并在 `存疑` 里写清是哪一类帖子、什么时间。

**不可作为结论**
- 模型记忆、聚合站的过期缓存、无出处的整理帖、AI 生成的岗位汇总。

## 招聘系统检索技巧（实测有效）

目标是**在一家公司里把岗位挖全**，而不是搜到一个算一个。

- **飞书招聘**（`xxx.jobs.feishu.cn`，智元、非夕等在用）：页面内的搜索框和筛选常常不生效，但 URL
  参数好用——`?keywords=算法&limit=50` 一次能拉 50 条，换 `keywords` 再搜「具身」「强化学习」
  「运动控制」「机械臂」合并去重。校招和社招入口不同：`/campusrecruitment`、`/socialrecruitment`、
  `/internrecruitment`、`/index`。
- **字节跳动**：`jobs.bytedance.com/campus/position?keywords=具身&limit=30`，列表页直接给城市、
  招聘项目（哪一届）、职位 ID 和详情链接。
- **列表页往往比详情页有用**：很多 ATS 的详情页要登录，但列表页已经带 JD 摘要，够写 `核心要求`。
- **纯静态抓取经常失败**：ATS 基本都是 JS 渲染，`WebFetch` 只能拿到标题。用浏览器打开并读页面文本，
  或者读它的接口返回。接口带签名参数时不要硬试翻页，签名通常和 offset 绑定，翻页会拿到重复数据。
- **学校就业网 / 校招公告聚合站**（牛企直聘、超级简历、各校就业信息网）适合找**公告和截止时间**，
  但发布日期要看清楚：同一个页面可能挂着上一届的公告。
- **官网打不开、接口被拒**都要如实记成 `访问失败` 并保留链接，不要当成「这家没岗位」。

**⚠️ 官网 careers 页 ≠ 公司的全部岗位**

很多公司的官网招聘页和实际招聘系统是两套内容，**岗位集合可能完全不重叠**。
Sharpa 的 `sharpa.com/pages/careers` 只列新加坡和美国的 18 个岗位、一个上海岗都没有，
而它的飞书门户上有 **151 个岗位、绝大多数在上海**。只看官网会直接得出「这家不在本地招人」的错误结论。

所以：**官网页只用来找 ATS 入口，岗位数以 ATS 为准**；两边都看到岗位时以 ATS 为准并记下差异。
跨国公司尤其要注意——英文站面向海外、中文 ATS 面向国内，是两拨 HC。

**⚠️ 猜 ATS 域名失败 ≠ 这家没有 ATS**

飞书招聘/Moka 的租户域名经常是**随机字符串**，不是公司名。Sharpa 的飞书门户是
`fcn5hvc5qbfs.jobs.feishu.cn`，而 `sharpa.jobs.feishu.cn`、`sharpa.zhiye.com`、
`mokahr/sharpa` 全部不存在——靠猜 slug 永远找不到。

猜不到时按这个顺序捞真实地址：

1. 官网招聘页里的「立即申请 / 投递简历」按钮指向的域名（傅利叶的 Moka 门户、非夕的飞书门户都是这么找到的）；
2. **中文校招公告**里的投递链接（Sharpa 的地址是从鼠鼠求职转载的 2026 春招公告里捞到的），
   聚合站、学校就业网、公众号推文都可能带；
3. 搜索 `公司名 + 投递链接 / 内推 / 校招官网`。

北森（`*.zhiye.com`）的租户名也可能带**数字后缀**：钛虎的门户是 `ti5robot1.zhiye.com`，
`ti5robot.zhiye.com` 不存在。猜 slug 时顺手试一下 `名字1`，但仍以公告里的投递链接为准。

**⚠️「0 个岗位」通常是假阴性，先排除这四种再下结论**

看到「无职位 / No position available / 开启新的工作（0）」时，**不要**直接写「该公司无在招岗位」，
按顺序排查：

1. **区域/语言设置**（最阴的一种）。招聘站会按 locale 过滤岗位，默认落在海外区就会全站显示无职位。
   检查并改写站点的区域标记再重载，例如蚂蚁招聘站把区域存在 `localStorage.LOCALE_KEY`，
   默认值是 `US` 时任何部门都是 0 条，改成 `CN`（同时 `LANGUAGE_KEY` 改 `zh-CN`）后立刻出现
   36 个岗位。中英文站的岗位集合往往也不同——中文站通常更全。
2. **过滤参数不通用**。同一站点的社招/校招/实习是不同板块，参数未必互通：蚂蚁社招支持
   `?depts=P1982` 按部门过滤，校招列表就不认 `depts`，只能用 `search=` 关键词。每个板块单独验证。
3. **板块路径不对**。飞书招聘有的租户只有 `/index`，`/campusrecruitment` 直接 404（速腾、钛虎、
   苏度、非夕都是这样），先探路径再下结论。
4. **确实空了**。提前批网申关闭后门户会清空（速腾 27 届网申 7/15 截止，之后门户显示 0 个岗位）。
   这种情况要写清「门户当前 0 个岗位 + 网申窗口已关闭」，而不是笼统的「未找到」。

只有四条都排除干净，才能写 `命中: 0`；否则写 `命中: null` 并在 `说明` 里讲清卡在哪一步。

## 薪资检索（单独一节，因为最容易漏）

国内招聘 JD 普遍不写薪资，**薪资必须单独跑一轮检索**，否则整张表会全是「未知」。

| 渠道 | 怎么用 | 可信度 |
|---|---|---|
| JD 明示区间 | 少数公司会写 | `官方JD` / 高 |
| 牛客「查薪资」 | `nowcoder.com/search?type=salary&query=<公司名>`，**必须用浏览器**（JS 渲染，WebFetch 只能拿到导航栏）。返回结构化的「公司 / 岗位 / 薪资 / 学历」用户自报记录 | `网传` / 低（多条互证可给中） |
| 牛客 offer 帖 | `?type=post&query=<公司名> offer 薪资`，能看到 `n×16`、`40+`、日薪等口径 | `网传` / 低 |
| 一亩三分地、脉脉、offershow | 多数要登录；拿不到就记 `访问失败`，别留空 | `网传` / 低 |
| 媒体赛道盘点 | 只能当**行业锚点**写进 meta，禁止安到具体公司 | `推断` / 低 |

**实测（2026-08）**：牛客薪资库里只有招人量大的公司有样本——智元有 3 条（算法约 50W、软开 50W+、算法 35K/月），
字节算法一大把；而苏度、穹彻这类新公司**一条都没有**。所以对早期公司，「薪资未知」是常态而不是失职。

**关键规则**：查过但查不到，薪资仍写 `未知`，同时在 `存疑` 里写「牛客薪资库<日期>检索无记录」。
「查过没有」和「根本没查」对用户是两件完全不同的事。口径也要记清楚：月薪×几个月、含不含签字费和股票、
白菜还是 SSP、数据是哪一年的。

## 判断优先级

同一条信息冲突时：官方当期页面 > 官方公众号当期推文 > 平台官方账号 > 社区当期帖 > 旧页面。
冲突且都当期时，两个值都写进 `存疑`，`hc状态` 或 `薪资可信度` 记 `未知`，不要挑对用户更好听的那个。

## 时效

- 每条来源记 `访问日期`；
- JD 页面记发布/更新时间，超过 30 天要在看板里提示复查；
- 秋招/春招节点变化快（提前批、正式批、补录），时间线单独确认。

## 红线

1. **不编造**：薪资、HC、截止时间、面试轮次、融资轮次，查不到写 `未知`。
2. **访问失败 ≠ 不存在**：页面打不开就记 `访问失败`，保留链接，之后重试。
3. **隐私**：只用公开职业信息。不收集私人手机号、私人邮箱、住址、私人社交账号，不猜邮箱格式；
   内推走公开渠道（官方内推码、公开的招聘邮箱、公司社交账号）。
4. **不代发**：可以起草内推私信、求职邮件、面试跟进信，由用户自己发送。
5. **不做承诺**：匹配度、通过率、薪资预期都是参考，不是保证。

## 找不到招聘系统入口时

- **官网地址靠搜索，不靠猜域名**。搜「<公司全称> 官网」「<品牌名> 招贤纳士」，或从工商信息、公众号简介、
  新闻稿里的链接拿官网；猜出来的域名连不上，**不能**得出「官网不可达」的结论。
  国地共建人形机器人创新中心曾被连猜三个域名（humanoid-robot.cn 等）都失败，整整两轮记为「官网不可达、
  岗位未知」，实际官网是开源社区名 `openloong.net`，上面挂着 28 个 27 届校招岗。
  记「访问失败」之前必须已经搜索过官网，并把搜索词写进覆盖记录。
- **先看官网「加入我们」按钮实际指向哪里**，不要凭搜索结果里的旧链接。公司会换招聘系统：
  高仙机器人的 Moka 校招页还能打开，但显示「暂无匹配职位」，真实的 42 个校招岗在官网指向的
  用友大易（`wecruit.hotjob.cn/<租户ID>/pb/school.html`）上。旧系统空页面是典型假阴性。
- **直接探测租户域名**：用公司英文名试 `https://<slug>.jobs.feishu.cn/`（存在返回 200，不存在返回 404），
  `lightwheel`、`morphicrobot` 都是这样找到的，搜索引擎并没有收录。北森 `<slug>.zhiye.com` 不管租户
  是否存在都返回 302，Moka `app.mokahr.com/campus-recruitment/<slug>` 都返回 200，这两家不能靠状态码判断。
- **官网只给邮箱或 BOSS 直聘链接**（鹿明、灵初）：把它记为官方渠道，岗位以该页面为准，并在 `存疑` 里注明
  未登录只能看到部分岗位。
- **注册地 ≠ 招聘地**：灵初智能主体和官网地址都在上海徐汇，但在招岗位全部在北京和深圳。城市以每个岗位
  写的工作地为准，公司在目标城市没有在招岗位时，只写覆盖记录（收录 0）并说明原因，不要硬收。

## 需要登录才能看全的渠道（BOSS 直聘等）

很多公司的官网「加入我们」直接指向 BOSS 直聘公司页（灵初、星海图、梅卡曼德），或者官方门户已经弃用、
岗位只挂在 BOSS 上（思岚）。BOSS 未登录时搜索不可用、公司页只显示部分岗位、详情被截断，
**这时官方门户「收录 0」不等于这家公司没岗**，必须走登录态再查一遍。

**登录由用户本人完成，助手不经手手机号和验证码：**

1. **优先用用户自己的 Chrome**（Claude in Chrome 扩展）：用户在 Chrome 里本来就登录着 BOSS，最省事。
   应用内置的浏览器面板打开 BOSS 登录页后用户侧是空白页（BOSS 的反自动化检测），实测不可用；
   没装扩展时先请用户安装并连接，或者请用户自己在 BOSS 上搜、把结果页文字贴回来。
   用内置面板的其他站点时：助手打开登录页，然后停下来请用户登录；
2. 用户自己在面板里输入手机号、收验证码、过滑块验证，登录好后回复一句「登录好了」；
3. 助手再用这个登录态去查。验证码、滑块、人机验证一律交给用户，助手不代填、不绕过。
   （用户也可以改用自己 Chrome 里已登录的会话。）

**登录态下只读，不替用户做任何动作：**

- 只打开搜索页、公司页、岗位详情页读内容；
- **绝不点「立即沟通」「投递」「感兴趣」「收藏」**——「立即沟通」会以用户名义给 HR 发消息；
- 不改简历、不改求职意向、不动任何账号设置，查完不退出登录；
- 放慢节奏（每页间隔几秒），出现安全验证就停下来请用户处理，不要反复重试。

**查法：**

- 城市反查：`https://www.zhipin.com/web/geek/job?query=<方向词>&city=101020100`（上海），
  方向词逐个搜（VLA、具身智能算法、强化学习 机器人、运动控制算法、灵巧手、机械臂 抓取），翻 3–5 页，公司名去重；
- 逐家补查：打开公司页「在招职位」，按城市筛目标城市，把官方门户里没有的对口岗补进来。

**写入规则：** BOSS 上的岗位来源类型记 `半官方`（官网明确指向 BOSS 公司页的可记 `官方`），
薪资区间记 `薪资来源: 官方JD`、可信度 `中`（BOSS 区间普遍偏宽）；同一岗位官方门户也有时以门户为准并去重；
在 `存疑` 里注明「来自 BOSS 直聘，HR 账号为某某，未在官方门户出现」。

## 不用浏览器拉全量岗位的接口（agent 并行时用，避免抢同一个浏览器）

- **飞书招聘**：先 `POST /api/v1/csrf/token` 拿 `atsx-csrf-token` cookie，再带 `x-csrf-token` 头
  `POST /api/v1/search/job/posts`（limit 100、offset 翻页），返回标题、城市、招聘类型。
  租户根路径存在返回 200、不存在返回 404，这个探测是可靠的；但很多公司用随机租户名或自定义域名
  （千寻 `nwd4iy9rd2s`、逐际 `career.limxdynamics.com`），猜不中时从官网 HTML 里取。
- **北森**：`POST https://<tenant>.zhiye.com/api/Jobad/GetJobAdPageList`，body 必须带 `PortalId` 和
  `"DisplayFields":["Category","Kind","LocId","Degree","YearsOfWorking","PostDate","Salary","Org"]`，否则城市为空。
- **Moka**：`POST app.mokahr.com/api/outer/ats-apply/website/jobs/v2`（limit 最大 50），响应是 AES-128-CBC 密文，
  密钥在响应的 `necromancer` 字段里；解密后首 16 字节是乱码，丢弃即可。
- **用友大易**（`wecruit.hotjob.cn/<租户>/pb/school.html`）、**Workday**、**SmartRecruiters** 都有公开列表接口。
- **猎聘企业页**能看到公司全部在招岗位和城市，是官网只给邮箱或跳第三方时的兜底；连续查询十来次后会被限流，
  限流后返回空结果，**不能把空结果当成没有岗位**。
- 公司官网的岗位列表经常不全或城市写得笼统（宇树官网只列 25 个杭州岗，北森里有 84 个；至简动力官网每个岗都写
  「北京/上海/苏州」），城市以招聘系统或 JD 正文为准。
- **BOSS 的移动站和 PC 站公司 ID 不通用**：`m.zhipin.com/companys/<id>.html` 里的 ID 拿去拼
  `www.zhipin.com/gongsi/job/<id>.html` 会打开另一家公司（如身、首形都踩过）。PC 站公司页未登录最多显示 15 个岗位，
  超出的部分和移动站的「热招职位」标签都要登录或在可见的浏览器里点开才能看到，查不全就写 `待补查`。
- **BOSS 未登录看到的岗位数本身就是缩水的**，不只是「最多显示 15 个」：梅卡曼德未登录显示「19 个在招」，
  登录后是 179 个；灵初未登录 18 个、登录后 55 个，其中上海的强化学习和运控岗只有登录后才出现。
  所以未登录的 BOSS 公司页只能用来确认「有岗」，不能用来确认「没岗」，结论要写 `待补查`。
- **登录态下的读法**（用户自己 Chrome 的会话）：公司页 `www.zhipin.com/gongsi/job/<id>.html` 逐页翻（`?page=N`），
  每张卡片是 `li.job-card-box`（岗位名、薪资、经验/学历、城市、`job_detail` 链接），读完按城市筛；
  没有公司页 ID 时用 `www.zhipin.com/web/geek/jobs?query=<公司名>&city=101020100` 搜。
  页面顶部有用户姓名和简历入口，不要读取或记录。
